# Kamino Earn Vault API Bug Report

**Date:** March 10, 2026  
**Reporter:** XmetaV / AkuaLabs  
**Severity:** Critical — deposit and withdraw transactions completely blocked  

---

## Summary

The Kamino Earn Vault transaction endpoints (`/ktx/kvault/deposit` and `/ktx/kvault/withdraw`) return a **500 Internal Server Error** for valid vault addresses. The error message indicates a null-reference crash server-side:

```
Cannot read properties of undefined (reading 'get')
```

This blocks all programmatic deposit/withdraw operations via the API.

---

## Affected Endpoints

| Endpoint | Method | Status |
|----------|--------|--------|
| `https://api.kamino.finance/ktx/kvault/deposit` | POST | **500** |
| `https://api.kamino.finance/ktx/kvault/withdraw` | POST | **500** |

## Proof That Validation Layer Works

Invalid vault addresses correctly return a 400 before hitting the broken code path:

```bash
curl -s -X POST 'https://api.kamino.finance/ktx/kvault/deposit' \
  -H 'Content-Type: application/json' \
  -d '{
    "wallet": "5aA3NB4HeKgXspMeL9No4W5aMLHnnAbAUUgDuifSGCAB",
    "kvault": "6LXCxeyMFREEhcGCRhKwdMqnRUaHMbVFgDcJmMBaGQYQ",
    "amount": "1000000"
  }'
```

**Response (correct 400):**
```json
{
  "statusCode": 400,
  "message": "Kamino Earn Vault 6LXCx... does not exist",
  "error": "Bad Request",
  "code": "KVAULT_NOT_FOUND"
}
```

This confirms the crash happens **after** vault validation, during transaction building.

---

## Likely Root Cause

The `"Cannot read properties of undefined (reading 'get')"` error pattern suggests something like:

```ts
// Pseudo-code — something in the tx builder is doing:
someMap.get(key)  // where someMap is undefined
```

Possible causes:
1. A vault state field (reserves map, token account map, or lookup table) isn't being loaded/initialized before the transaction builder accesses it
2. An internal cache or connection object is `undefined` at the point of `.get()` call
3. A dependency (e.g., `@solana/web3.js` or address lookup table resolver) changed its return shape in a recent update

## Impact on Our Integration

We integrate Kamino Earn vaults via an SDK-first approach with API fallback. Both paths are affected:

- **SDK path:** `KaminoVault.depositIxs()` / `withdrawIxs()` — works for instruction building but requires us to handle address lookup tables, which the API was meant to simplify
- **API path:** Completely blocked by this 500 error

Our lending endpoints (`/ktx/deposit`, `/ktx/borrow`, `/ktx/repay`, `/ktx/withdraw`) work fine — only the Earn vault endpoints are affected.
